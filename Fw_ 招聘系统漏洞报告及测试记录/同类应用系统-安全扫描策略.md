# 同类应用系统安全扫描策略

> **依据**：《招聘系统-漏洞记录及修复情况记录表-汇总》（主表 41 条 + 补充登记 补充-02～06）、`code-audit-report.md`、`SECURITY-REMEDIATION.md`  
> **目标**：对 **JeecgBoot / 低代码后台 + Vue 前端 + 招聘/人事类业务** 的 Web 应用，形成可重复执行的扫描与验收方法，用于新项目上线前、大版本发布后与年度复测。

---

## 1. 适用范围与系统画像

### 1.1 适用系统类型

| 特征 | 说明 |
|------|------|
| 技术栈 | Java（Spring Boot）+ Shiro/JWT + MyBatis；前端 Vue3；常见集成 JimuReport、Druid、Quartz、Swagger/Knife4j |
| 业务形态 | 多角色（匿名访客、求职者/应聘者、业务审核、系统管理员）；大量 **PII**（简历、身份证、联系方式） |
| 部署形态 | Nginx 静态前端 + `/xxx-boot` API；可能含宝塔、外置 MySQL、Redis、邮件/短信/AI 第三方 |

### 1.2 不适用或需裁剪的场景

- 纯静态站、无登录、无文件上传：可跳过 IDOR、JimuReport、Quartz 等章节。
- 非 Jeecg 系自研框架：保留 **通用 Web 安全章节**（认证、授权、上传、配置、依赖），替换组件专有路径。

### 1.3 扫描原则

1. **先配置后接口**：生产误用 `dev` profile 会连锁放大 Swagger、报表、堆栈泄露等问题（对应 C-001、VULN-005/017/018/024）。
2. **多角色矩阵**：同一 URL 用 **匿名 / 低权限 / 高权限** 各测一遍；招聘类系统低权限账号往往可注册（对应 VULN-001/002/019/040 等）。
3. **攻击链优先于单点**：按文末「攻击链」编排用例，避免只扫 AWVS 告警而漏掉 IDOR 组合（见第 6 节）。
4. **证据可复现**：每条发现需保留 HTTP 原文、截图、账号角色、时间；编号对齐 `VULN-xxx` 或项目自建编号。

## 2. 扫描阶段与交付物

| 阶段 | 内容 | 主要手段 | 交付物 |
|------|------|----------|--------|
| **S0 资产与范围** | 域名/IP、内外网、API 前缀、角色账号、是否含报表/低代码 | 访谈 + 配置清单 | 《扫描范围说明》 |
| **S1 暴露面与配置** | Profile、Actuator、Swagger、Druid、Nginx、TLS、安全响应头 | 端口扫描、目录探测、配置审计 | 配置项对照表 |
| **S2 认证与会话** | 登录、验证码、口令传输、JWT、注销、锁账户 | 手工 + Burp | 认证测试记录 |
| **S3 授权与业务** | IDOR、水平/垂直越权、匿名接口 | 多角色手工 + 自动化 | 越权用例表 |
| **S4 输入与文件** | 上传、下载、XSS、SQLi、SSRF、路径穿越 | 手工 + DAST（AWVS 等） | 漏洞条目 |
| **S5 组件与依赖** | Shiro、SnakeYAML、JimuReport、fastjson 等 | SCA + 版本核对 + 专项 PoC | 依赖风险表 |
| **S6 基础设施** | 数据库出网、面板、备份、凭据 | 配置审计 + 端口验证 | 基础设施项 |
| **S7 复测与闭环** | 对照修复版本逐项关闭 | 回归脚本 + 签字 | 《漏洞记录及修复情况记录表》 |

**建议周期**：首次全量 S0～S6；每次发版至少 S1+S3+S4 抽样；年度全量。

**推荐工具（可替换）**：

- DAST：AWVS / Nessus Web / Burp Scanner  
- 手工：Burp Suite、curl、Postman  
- 依赖：OWASP Dependency-Check、Maven `dependency:tree`  
- 配置：本仓库 `scripts/security-remediation-verify.ps1`（环境变量自检，**不替代**渗透）

## 3. 测试账号与环境要求

### 3.1 最低账号矩阵

| 角色 | 用途 | 招聘系统对应经验 |
|------|------|------------------|
| 匿名 | 未登录可访问面 | 岗位列表、部门树、登录 RSA 公钥等 |
| 低权限业务用户 | 水平越权主测账号 | 求职者 `test-qz` 类账号 |
| 中权限业务用户 | 审批流、部门数据 | 部门审核、人力审核 |
| 系统管理员 | 垂直越权对照 | `admin` / `hradmin` |
| 禁用/锁定账号 | 账户策略 | 连续失败锁定、统一错误文案 |

### 3.2 环境约束

- **扫描环境**：优先与生产同架构的 **预发/灰度**；禁止未授权对生产做破坏性测试（RCE、删库、批量导出 PII）。
- **生产 profile**：必须确认 `spring.profiles.active=prod`（或等价），且 `knife4j.production=true`、报表 `lowCodeMode=prod`（C-001）。
- **网络**：区分 **应用层** 与 **数据库/面板是否出网**（VULN-032、C-002）。

## 4. 分类检查清单（映射历史漏洞）

以下按 **安全域** 组织；括号内为招聘系统已登记编号，新项目可复用检查项并重新编号。

### 4.1 部署与配置安全（P0）

| # | 检查项 | 方法 | 通过标准 | 参考编号 |
|---|--------|------|----------|----------|
| Cfg-01 | 运行 Profile 是否为生产 | 查启动参数、`/actuator/env`（若暴露）、JAR 内 `application.yml` | 非 `dev`；生产安全项生效 | C-001 |
| Cfg-02 | 敏感配置是否硬编码 | 反编译/读 JAR 配置、任意文件读后的配置泄露 | DB/邮件/AI/签名密钥均来自环境变量 | C-002, VULN-027 |
| Cfg-03 | 错误页与堆栈 | 触发 404/500 | 无完整堆栈、无 SQL 细节 | C-001 |
| Cfg-04 | CORS / 安全头 | 预检请求、响应头 | 生产 Origin 白名单；`X-Frame-Options` 等按需 | SECURITY-REMEDIATION |
| Cfg-05 | JWT/签名密钥强度 | 环境变量 + 启动校验脚本 | 长度足够、非默认值、与前端构建一致 | VULN-022, VULN-028 |
| Cfg-06 | Token 是否允许出现在 URL | 抓包登录、导出链接 | 生产 `allow-token-in-query=false` | SECURITY-REMEDIATION |
| Cfg-07 | 进程权限与本地文件 | 容器/主机核查 | 应用非 root；限制可读路径 | VULN-026 |
| Cfg-08 | 前端目录误解析 | 对静态目录请求 `.php` 等 | 无 PHP/脚本执行 | VULN-033 |
| Cfg-09 | 主机面板与旁路 | 端口扫描、默认路径 | 面板不对外；API Key 未泄露 | VULN-030, VULN-031 |

**快速命令示例（按实际 context-path 替换）：**

```bash
# Profile / 环境泄露（需授权）
curl -s "https://<host>/<boot>/actuator/env" -H "X-Access-Token: <token>"

# 生产应不可访问或需 admin
curl -s -o /dev/null -w "%{http_code}" "https://<host>/<boot>/doc.html"
curl -s -o /dev/null -w "%{http_code}" "https://<host>/<boot>/druid/index.html"
```

### 4.2 认证、验证码与会话（P0～P1）

| # | 检查项 | 方法 | 通过标准 | 参考编号 |
|---|--------|------|----------|----------|
| Auth-01 | 登录验证码 | 关闭验证码配置、空验证码、固定验证码重放 | 生产强制开启且服务端校验 | 补充-06 |
| Auth-02 | 用户名字段枚举 | `checkOnlyUser`、注册、找回密码 | 统一提示；限流+验证码 | 补充-03, 补充-04 |
| Auth-03 | 手机号/邮箱枚举 | 发短信、绑定、找回 | 不返回「已注册/未注册」差异 | 补充-05 |
| Auth-04 | 口令传输 | 抓包登录请求 | 优先 RSA 一次性密钥或纯 TLS；无匿名下发长期 AES 密钥 | VULN-004, VULN-038 |
| Auth-05 | 密码重置接口 | GET 带密文参数、越权改他人密码 | 仅 POST + 鉴权；GET 关闭 | SECURITY-REMEDIATION |
| Auth-06 | JWT 有效期与吊销 | 配置 + Redis 白名单行为 | 有效期 ≤8h（按策略）；登出失效 | C-004, VULN-028 |
| Auth-07 | 会话固定 / 并发登录 | 重复登录、旧 Token | 按产品策略一致 | — |

### 4.3 授权与 IDOR（P0，招聘/人事类重点）

**通用方法**：

1. 用 **用户 A** 创建资源，记录 `id` / `applyId` / `resumeId`。  
2. 用 **用户 B**（同角色或更低权限）访问 A 的读写接口。  
3. 用 **匿名** 访问需登录接口。  
4. 对「管理员列表」接口（`/list`）与「我的」接口（`/listMine`）**成对检查**是否缺 `create_by` / 数据权限注解。

| # | 检查项 | 方法 | 通过标准 | 参考编号 |
|---|--------|------|----------|----------|
| Authz-01 | 用户/员工列表 | 低权限 GET 用户分页 | 403 或仅本人可见字段 | VULN-001 |
| Authz-02 | 简历列表/详情/编辑 | list vs listMine；PUT 他人 id | 无法读改他人简历 | VULN-002, VULN-020 |
| Authz-03 | 简历导出 Word/PDF | 枚举 `applyId` | 403 | B-003 |
| Authz-04 | 岗位/申请列表 | 不传审批节点、换参数 | 无全量他人申请 | B-004, VULN-009 |
| Authz-05 | 附件下载/路径 | 列表接口是否返回绝对路径 | 仅授权下载；路径不可预测 | VULN-007, VULN-008 |
| Authz-06 | 系统管理 API | 数据源、Quartz、定时任务 | `@RequiresPermissions` 齐全 | VULN-019, VULN-040, VULN-041, VULN-023 |
| Authz-07 | 匿名业务接口 | 无 Token 访问岗位/组织 | 仅公开只读数据；无 PII | VULN-009, 补充-CZ-001 |

## 5. 攻击链驱动场景（必跑）

将单点检查串联为 **场景用例**，用于发现「单项扫描通过但整体仍不安全」的情况。

### 链 A：零认证 → 全量 PII（招聘系统已验证）

```
匿名/低权限 → 岗位与组织信息 → 用户列表 → 简历列表 → 附件路径/导出 Word
```

**验收**：低权限账号 **无法** 完成链上任一步获取他人 PII。

### 链 B：低权限 → RCE / 数据库

```
低权限 JWT → JimuReport testConnection / dataSource 添加 → JDBC 反序列化或直连外置 DB
```

**验收**：无法建立任意外连 JDBC；无法以应用外凭据连生产库（C-002, VULN-032）。

### 链 C：低权限 → 管理员能力

```
低权限 → Actuator httptrace 窃取 admin Token → 长有效期 JWT → Quartz/系统配置写操作
```

**验收**：Actuator 不可访问；Token 短期有效；Quartz/数据源仅管理员权限（VULN-010, C-004, VULN-023）。

## 6. 自动化扫描策略（AWVS 等 DAST）

### 6.1 建议策略

| 项 | 建议 |
|----|------|
| 扫描配置 | Full Scan + Authentication（录制登录；含验证码时需插件或手工 Cookie） |
| 范围 | 仅 API 与前端域名；**排除**  destructive 检测项若厂商不允许 |
| 角色 | 至少 **未认证** + **低权限** 两次扫描 |
| 限流 | 与运维约定 QPS，避免打挂生产 |
| 人工补测 | AWVS 对 **IDOR、业务越权、JDBC SSRF、验证码逻辑** 检出率有限，S3/S4 必须手工 |

### 6.2 应对「误报 / 漏报」

| 现象 | 处理 |
|------|------|
| 大量 XSS 在富文本 | 结合存储上下文判断是否需修复或接受（补充-02） |
| SQLi 在报表接口 | 按 VULN-018 手工验证 |
| 无 IDOR 告警 | 仍执行第 4.3 节矩阵 |
| Swagger 200 | 一律按 VULN-005 失败项 |

## 7. 白盒 / 代码审计补充（发版前或重大改造）

与黑盒对照的最小代码审计清单（Jeecg 定制项目）：

1. **Controller**：所有 `/list` 是否缺数据权限；`edit/delete/export` 是否校验 `create_by`。  
2. **ShiroConfig**：`anon` 列表是否含 `/jmreport/**`、`/druid/**`、报表大屏。  
3. **配置文件**：`spring.profiles.active`、凭据占位符、JWT 过期时间。  
4. **上传过滤器**：`SsrfFileTypeFilter` 白名单是否含 `svg` 等。  
5. **权限注解**：`SysDataSourceController`、`QuartzJobController` 等系统接口。  
6. **调试代码**：`@Profile("dev")` 或删除 `testTemplates` 类接口。

可参考本仓库 `Fw_ 招聘系统漏洞报告及测试记录/code-audit-report.md` 的条目结构输出 **C-xxx / B-xxx** 编号。

## 8. 判定、分级与记录模板

### 8.1 严重级别（与汇总表对齐）

| 等级 | 典型场景 |
|------|----------|
| 严重 | 未授权全量 PII、生产配置/凭据泄露、任意文件读导致全盘可读、数据库直连 |
| 高危 | IDOR 批量导出、Swagger/报表 RCE 链、弱口令监控台、低权限写系统配置 |
| 中危 | 枚举、XSS、Actuator 信息泄露、密钥下发不当、Quartz 信息泄露 |
| 低危 | 调试接口、信息提示过详 |

### 8.2 单条漏洞记录字段（复用汇总 docx）

每条至少包含：**漏洞名称、编号、等级、路径/URL、描述、修复建议、PoC 证明、修复方案、涉及文件、复测结果、签字确认**。

### 8.3 闭环通过标准

| 状态 | 含义 |
|------|------|
| 已修复 | 预发/生产可验证；PoC 不可复现 |
| 风险接受 | 书面审批 + 补偿控制 + 到期复评 |
| 误报 | 说明原因并归档 |

发版后执行：`scripts/security-remediation-verify.ps1`（严格模式）+ 本章 **P0 检查项** 全绿 + 攻击链 A/B/C 不可复现。
