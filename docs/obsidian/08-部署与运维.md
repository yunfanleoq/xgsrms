## 构建发布（本地 Windows）

### 1. 全量构建

```powershell
Set-Location I:\cursorProjects\xgsrms
# 方式 A：环境变量
$env:JEECG_SIGNATURE_SECRET='你的hex密钥'
powershell -ExecutionPolicy Bypass -File .\scripts\build-release.ps1
# 方式 B：local-signature.env（gitignore）
powershell -ExecutionPolicy Bypass -File .\scripts\build-release.ps1
```

产出：

- `jeecg-boot\jeecg-module-system\jeecg-system-start\target\jeecg-system-start-*.jar`
- `jeecgboot-vue3\dist\`

`build-release.ps1` 将同一密钥写入 `VITE_GLOB_SIGNATURE_SECRET` 与 `JEECG_SIGNATURE_SECRET`。

### 2. 部署后端

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-backend-xgs-server.ps1
```

流程：scp JAR + `deploy-backend-xgs-server.sh` → 远程安装并重启。

### 3. 部署前端

```powershell
Set-Location I:\cursorProjects\xgsrms\jeecgboot-vue3
.\scripts\deploy-frontend-xgs-server.ps1
```

无 `dist` 时会自动 `pnpm run build`，再 rsync 到 Nginx 目录。

### 4. 收尾脚本

- `scripts/stop-rms-backend.sh` — 彻底停止后端（逐个 kill PID + runuser + 8080 端口，最多 5 轮）
- `scripts/finish-rms-deploy.sh` — 服务器侧前后端收尾（内置调用 stop-rms-backend）
- `scripts/restart-rms-backend.sh` — 停干净后重启后端
- `scripts/ensure-rms-security-env.sh` — 补全 `rms.env` 安全项（CORS、禁止 URL Token 等）

## 生产环境变量（`rms.env`）

路径：`/www/wwwroot/rms/backend/rms.env`。模板：`deploy/rms.env.example`。

| 变量 | 生产建议 | 说明 |
|------|----------|------|
| `JEECG_SIGNATURE_SECRET` | 必填 | 与前端构建 `VITE_GLOB_SIGNATURE_SECRET` 一致 |
| `JWT_SECRET` | 必填 | JWT 签名，≥32 字符 |
| `CORS_ALLOWED_ORIGINS` | 必填 | 逗号分隔 Origin，如 `http://10.28.12.15,https://10.28.12.15` |
| `JEECG_SECURITY_ALLOW_TOKEN_IN_QUERY` | **`false`** | Cfg-06：禁止 `?token=` 传 JWT |
| `MYSQL_*` / `REDIS_PASSWORD` | 必填 | 数据库与 Redis |

补全安全项（幂等）：

```bash
bash ~/ensure-rms-security-env.sh
sudo bash ~/restart-rms-backend.sh
```

启动日志应出现：`安全策略: allowTokenInQuery=false`。

## 监控与日志

- 单体日志：Spring Boot 默认 logging + 应用 `logback-spring.xml`
- 若启用 Druid：注意控制台暴露与认证（[[09-安全与扫描]]）
- 微服务监控模块在 `jeecg-server-cloud`（生产未作为主路径）

## 回滚策略

1. 保留上一版 JAR 与 `dist` 备份（部署脚本带时间戳目录 `~/rms_backend_build`）
2. MySQL 升级前必须备份
3. 前端 rsync `--delete` 会清空旧静态文件，回滚需备份 dist
